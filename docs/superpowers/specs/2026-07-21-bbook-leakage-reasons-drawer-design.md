# Bbook 漏网原因与用户抽屉设计

## 目标

在现有“验证期客户净 P&L > 100”的 Bbook 漏网列表中，为每个用户展示可读的 Bbook 分流原因，并允许点击用户复用现有 Abook 用户分析抽屉。页面首次加载不增加用户明细查询；只有点击用户时才调用当前已有的账户明细接口。

## 方案

后端在账户路由结果中生成 `bbook_reason_tags`，并在 `build_misjudge_summary` 的漏网条目中透传。标签来源按优先级组织：

1. 马丁确认阻断、快照不可用或其他马丁阻断状态；
2. Abook 规则未通过；
3. 稳定性、样本量、胜率、盈亏比、集中度、杠杆等已有 `selection_flags` 的可读名称。

前端将漏网摘要行按 `(platform, login)` 与 `data.accounts` 中的完整账户对象关联。命中时点击直接触发当前 `openAccount`，因此抽屉继续使用既有的用户指标、去极值和 Entry/Exit markout；关联失败时使用摘要对象作为安全兜底。漏网表新增标签列，保留现有排序和金额筛选。

## 性能与错误处理

不在 `loadAnalysis` 或 `loadBook` 阶段请求额外用户详情。点击抽屉仍复用已有的单用户接口、请求竞态保护和遮罩点击关闭逻辑。原因标签即使字段缺失也至少返回“Bbook（未通过 Abook 路由）”，避免出现空原因。

## 验证

- 后端测试验证马丁阻断、规则失败和风险 flag 能形成稳定标签。
- 前端契约测试验证漏网原因列、可点击行和抽屉复用。
- 全量 pytest 与 Vite production build 必须通过。
