# Abook 7 月验证参数回测记录

## 结论

在不读取 `may_june_mean_bps_gt_0.05_logins.csv` 的前提下，使用 5–6 月筛选指标回测 7 月 1–13 日验证期，原默认组合只留下 1 个 Abook Core 用户，验证理论增量为 `-264.52 USD`。

当前采用的平衡组合为：

- 交易数 `>= 20`
- 活跃交易天数 `>= 10`
- 胜率 `>= 50%`
- Profit Factor `> 1`
- Payoff Ratio `>= 0.8`
- 平均日利润 `> 0 USD`
- 盈利月份占比 `>= 50%`
- 盈利日率 Wilson 95% 下限 `>= 55%`
- 稳定性评分 `>= 70`
- Top1 日利润贡献率严格 `< 20%`
- 峰值杠杆率 `<= 200`
- 峰值杠杆超过 200 时，中位持仓 `<= 300 秒` 才允许例外

真实 API 结果为 35 个 Abook Core 用户，7 月验证理论增量 `$7,883.12`，继续盈利率 `68.6%`。7 月有交易的 28 个用户中，24 个盈利、4 个亏损；验证期用户净 P&L 为 `$7,883.12`，因为当前 Abook 仍假设外部成交利润为 0，所以这也是页面展示的理论增量。

## 杠杆分布

本地风险快照包含 31,896 个用户，其中 12,144 个用户的上月余额为正，19,752 个用户的上月余额小于等于 0 并跳过杠杆过滤。正余额用户的峰值杠杆分布长尾明显，峰值超过 200 的有 5,526 个；其中筛选期中位持仓不超过 300 秒的有 2,138 个。

因此没有使用极低的杠杆阈值 5：它会把大量小余额、短持仓用户一并排除。页面现在只对正余额用户执行峰值杠杆上限；零余额或负余额用户仍执行其他筛选规则。高杠杆例外同时写入本地快照和服务层，避免本地 SQL 过滤与服务层判断不一致。

## 解释与限制

Profit Factor 是阶段总盈利除以总亏损绝对值，不是单笔盈亏比；Payoff Ratio 是平均盈利交易除以平均亏损交易绝对值。两者保留为不同过滤条件。

7 月 1–13 日是部分月份，以上参数组合是在当前样本上的验证结果，不代表未来收益保证。后续应继续滚动验证，并记录每次参数变更前后的候选人数、继续盈利率和理论增量，避免只根据单个部分月份调参。
